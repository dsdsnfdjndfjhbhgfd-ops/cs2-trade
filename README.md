# CS2 Trade

Сайт со свечными графиками цен и объёмов продаж скинов CS2, как на криптобирже. Цены собираются
с Skinport, market.csgo.com, Waxpeer, Lis-Skins и Steam; на странице скина — таблица цен по площадкам
с самым дешёвым предложением.
Хостится на GitHub Pages: https://dsdsnfdjndfjhbhgfd-ops.github.io/cs2-trade/

## Как это работает

GitHub Pages отдаёт только статические файлы, поэтому данные собирает GitHub Actions:

1. Каждые 15 минут запускается `.github/workflows/update.yml`.
2. `scripts/collect.mjs` три раза с паузой 5 минут снимает минимальную цену и число лотов по всему рынку CS2
   с открытых API площадок (при пуше и ручном запуске — один раз, чтобы сайт обновился быстрее):
   - **Skinport** — ещё и продажи за 24ч/7д/30д/90д (на них считаются объёмы и ликвидность);
   - **market.csgo.com**, **Waxpeer**, **Lis-Skins** — общий список цен, один запрос на площадку;
   - **Steam Community Market** — текущая цена и продажи за 24ч для 40 самых оборотных скинов (один раз за запуск).
3. Из свежих цен Skinport, market.csgo.com, Waxpeer и Lis-Skins считается **«Рынок»** — медиана самых дешёвых
   предложений. Медиана не даёт одной площадке с подозрительно дешёвым или дорогим лотом сдвинуть цену.
   Steam в неё не входит: там цены выше из-за комиссии, а деньги со счёта Steam нельзя вывести.
4. Наблюдения дописываются в свечи (15-минутные хранятся 7 дней, часовые — 45 дней, дневные — всегда)
   в `data/items/*.json`, отдельно по каждой площадке и для «Рынка».
5. Данные сохраняются в ветку `data` (один коммит, перезаписывается, чтобы репозиторий не разрастался),
   а сайт вместе с данными публикуется на Pages.

Фронтенд — `index.html` + `assets/app.js`, графики на [TradingView Lightweight Charts](https://github.com/tradingview/lightweight-charts).

## Что показывают графики

- **Свеча** — минимальная цена предложения (самый дешёвый лот) за период: открытие, максимум, минимум, закрытие.
  Площадка выбирается в списке над графиком; по умолчанию — «Рынок».
- **Столбики** — число продаж за последние 24 часа (на недельном таймфрейме — сумма продаж за неделю).
- **Лоты** — сколько предложений выставлено (на «Рынке» — на всех площадках вместе; линия, кнопка «Лоты»).
- **MA 7 / MA 25** — скользящие средние цены закрытия за 7 и 25 последних свечей.
- **Сравнение** — пунктиром цена на другой площадке (выбирается в списке «Сравнить…»), в легенде — разница в процентах.

Управление графиком:

- **Период** (1Д, 1Н, 1М, 3М, Всё) показывает последние сутки, неделю и т. д. и сам подбирает подходящую свечу;
  свечу (15м, 30м, 1ч, 4ч, 1д, 1н) можно поменять и вручную.
- **Вид**: свечи, линия или область. Пока истории мало, линия читается проще.
- Колёсико мыши или щипок — масштаб, перетаскивание — прокрутка, двойной клик или кнопка ↔ — вся история.
- Под графиком — итог за видимый период: изменение цены, максимум и минимум с датами, средние продажи.
- Кнопка ↓ сохраняет картинку графика с названием скина и датой, ⛶ — во весь экран.
- Время показывается по часовому поясу пользователя. Все настройки графика запоминаются в браузере.

История начинает копиться с первого запуска: в первые часы на графике будет мало свечей.

## Сортировка и ликвидность

Список скинов сортируется по обороту, цене, ликвидности, числу продаж и изменению за 24ч. Направление
переключается кнопкой ↓/↑ рядом с выбором или повторным нажатием на заголовок колонки. Выбор запоминается в браузере.

**Ликвидность** — оценка от 0 до 100 относительно остальных отслеживаемых скинов:
на 65% — сколько штук продаётся в день на Skinport (за 7 дней, если нет — за 30), на 35% — какая доля выставленных
лотов уходит за день. Столбики у названия: 3 зелёных — высокая (67+), 2 жёлтых — средняя (34–66), 1 красный — низкая.

## Загрузка прошлой истории из Steam (необязательно)

Steam отдаёт историю цен за годы, но только авторизованным пользователям:

1. Войдите на steamcommunity.com, откройте инструменты разработчика → Application → Cookies и скопируйте
   значение `steamLoginSecure`. Это ключ к вашему аккаунту: не показывайте его никому.
2. В репозитории: Settings → Secrets and variables → Actions → New repository secret, имя `STEAM_LOGIN_SECURE`.
3. Actions → «Update prices and deploy» → Run workflow → отметить «Загрузить прошлую историю из Steam».

## Вход на сайт

Кнопка «Войти» в шапке открывает окно: вход через Steam или регистрация и вход по почте и паролю.
Пользователи хранятся в Supabase Auth (проект `cs2-trade`). Сессия хранится в браузере и продлевается сама.

### Почта и пароль

Регистрация и вход идут напрямую в Supabase Auth. После регистрации приходит письмо со ссылкой;
ссылка подтверждает почту и возвращает на сайт уже вошедшим. Пароль — не короче 8 символов.

Что нужно настроить в панели Supabase (проект `cs2-trade`):

1. **Authentication → URL Configuration**: Site URL — `https://dsdsnfdjndfjhbhgfd-ops.github.io/cs2-trade/`,
   в Redirect URLs добавить его же (и `http://localhost:8765/**` для локальной проверки). Иначе ссылка
   из письма поведёт на `localhost:3000`.
2. **Authentication → Emails → SMTP Settings**: свой почтовый сервис (Resend, Brevo, Postmark и т. п.).
   Встроенный сервис Supabase отправляет письма только участникам команды проекта и всего несколько в час,
   остальные получат ошибку «Сайт пока не может отправлять письма на этот адрес».

### Steam

Сайт статический, поэтому вход через Steam проверяет edge-функция Supabase `steam-auth`
(исходник — `supabase/functions/steam-auth/index.ts`):

1. Сайт отправляет браузер на функцию, она — на страницу входа Steam (OpenID). Пароль вводится только на steamcommunity.com.
2. Steam возвращает браузер на функцию; та проверяет подпись ответа у самого Steam, создаёт или находит
   пользователя Supabase и возвращает браузер на сайт с сессией.
3. Имя и аватар берутся из открытого профиля Steam. Если задать функции секрет `STEAM_API_KEY`
   (ключ с https://steamcommunity.com/dev/apikey), они будут браться через Steam Web API.

У Steam-пользователей служебный адрес `steam_<SteamID>@users.cs2-trade.invalid`, а настоящий Steam-аккаунт
отмечен `steam_id` в `app_metadata`, который пользователь изменить не может. Если кто-то заранее зарегистрирует
такой адрес по почте, функция удалит этот аккаунт и создаст настоящий: так нельзя подложить аккаунт со своим паролем.

После входа на сайт можно вернуться только на адреса из списка: сайт на GitHub Pages и `localhost`.
Другие адреса добавляются секретом функции `ALLOWED_REDIRECTS` (префиксы через запятую).
Функцию нужно деплоить с выключенной проверкой JWT (`supabase functions deploy steam-auth --no-verify-jwt`).

## Настройки

Переменные окружения сборщика: `POLLS` (сколько раз опросить площадки за запуск, по умолчанию 1;
в расписании — 3), `POLL_INTERVAL_S` (пауза между опросами, 300), `MAX_ITEMS` (сколько скинов отслеживать, по умолчанию 300) и
`STEAM_ITEMS` (сколько из них опрашивать в Steam за запуск, по умолчанию 40).

Локальный запуск: `node scripts/collect.mjs`, затем `python3 -m http.server` в корне репозитория.

## Ограничения

- Skinport API: не чаще 8 запросов за 5 минут, ответ кэшируется 5 минут. Мы делаем 4 запроса за запуск
  (история продаж и три снимка цен с паузой 5 минут).
- 15-минутная свеча строится из 1–3 снимков цены, поэтому её максимум и минимум приблизительные.
- Steam жёстко ограничивает частоту запросов, поэтому опрашивается только часть скинов, с паузой 3,5 с.
- CSFloat, Buff163, DMarket, BitSkins и другие площадки требуют API-ключ или вход, закрыли открытый API
  или запрещают автоматический сбор, поэтому пока не подключены.
- У market.csgo.com и Waxpeer в списке цен нет ссылки на страницу скина, поэтому ссылка ведёт на поиск по названию.
- Расписание GitHub Actions не точное: запуск может задерживаться на 5–20 минут, а в часы пиковой нагрузки
  GitHub иногда пропускает запуски по расписанию — тогда в 15-минутных свечах будут пропуски.
